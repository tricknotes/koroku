# API トークンの作り方と置き場所

Claude Code が koroku の状態を読むための、読み取り専用のトークンを用意する。作るのも置くのも利用者が行う。

## 作る

1. koroku の管理画面を開き、右上のユーザーメニューから「セキュリティ」を開く。
2. 「API トークン」の「トークンを作成」を押す。直近 10 分以内にログインしていなければ、先に GitHub での再ログインを求められる。
3. 名前（どこで使うかのメモ。例「ノート PC の Claude Code」）と有効期限（7 日・30 日・90 日。最長 90 日）を選んで作成する。
4. 表示された `koroku_ro_...` の値をコピーする。**この値は一度しか表示されない。** なくしたら作り直す。

トークンで読めるのは、アプリ、デプロイとデプロイログ、サービスの状態、実行ログ、必要な環境変数の照合（キーと設定済みかどうかだけ）、ホストの状態。環境変数の値、バックアップ、セッションは読めず、変更系の操作は一切できない。

## 置く

シェルの環境変数にする。リポジトリにはコミットしない。

```sh
export KOROKU_URL=https://console.dev.example.com
export KOROKU_TOKEN=koroku_ro_...
```

置き場所の例:

- `~/.zshrc` や `~/.bashrc`（すべてのリポジトリで使う）。
- direnv の `.envrc`（そのリポジトリでだけ使う）。`.envrc` を `.gitignore` に入れるか、グローバルの ignore（`~/.config/git/ignore`）に入れて、コミットされないことを `git check-ignore .envrc` で確かめる。
- パスワードマネージャーの CLI から読み込む（例: `export KOROKU_TOKEN="$(op read op://...)"`）。

Claude Code を起動する前に設定しておく（起動中のセッションには、あとから設定した環境変数は届かない）。

## 失効させる・作り直す

- 管理画面の「セキュリティ」→「API トークン」で「失効」を押すと、すぐに使えなくなる。マシンを手放す、値を誤って共有した、心当たりのない「最終利用」がある、といったときに使う。
- 期限が切れると、スクリプトは `the token was refused` で止まる。新しいトークンを作って `KOROKU_TOKEN` を差し替える。
- 値は `koroku_ro_` で始まるので、GitHub の push protection などのシークレットスキャナーに、この接頭辞をカスタムパターン（`koroku_ro_[A-Za-z0-9_-]{43}`）として登録しておくと、誤ってコミットしたときに気づける。
